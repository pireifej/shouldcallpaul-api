---
name: Resume speech display fields
description: Keep guest-speaker metadata compatible with the separate website's speech detail display.
---

Reuse the existing Toastmasters/speech detail fields for new speech entries.
Put supplemental event information such as time, timezone, guest role, open-house
context and street address in the description instead of introducing extra
display fields. Omit contest and placement when an appearance was not a contest.

**Why:** The user reported that the separate GUI exposed too many fields after
a guest-speaker entry introduced additional detail keys, and requested the same
field structure as the other Toastmasters entries.

**How to apply:** When adding or updating speeches, keep visible details limited
to applicable existing fields. Do not invent contest results to fill the schema.
